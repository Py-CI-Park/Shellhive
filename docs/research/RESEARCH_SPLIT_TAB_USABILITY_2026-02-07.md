# Shellhive 분할/탭 사용성 개선 연구 메모 (2026-02-07)

## 1. 배경

사용자 피드백 기준으로 현재 분할/탭 UX의 핵심 불편은 다음 두 가지였습니다.

1. 분할 패널 클릭 시 분할 상태가 풀리고 단일 화면으로 보이는 문제
2. 레이아웃(탭/그리드) 선택 진입이 분산되어 직관성이 낮은 문제

## 2. 원인 분석

### 2.1 분할 클릭 시 단일 화면 전환

- `activateSession()` 호출 시 항상 `restoreTabLayout()`를 수행
- 분할 중 클릭한 세션에 저장된 레이아웃이 없으면 `splitMode=false`로 복원
- 결과적으로 사용자는 "패널 선택" 의도였지만 "분할 해제처럼 보이는 전환"을 경험

## 3. 개선 원칙

1. 분할 컨텍스트에서는 "선택"과 "레이아웃 전환"을 분리
2. 분할 해제는 명시 액션(합치기/분할 종료)로만 수행
3. 자주 쓰는 레이아웃 진입점은 툴바/단축키/팔레트에서 동일 의미로 제공

## 4. 반영한 개선 사항

### 4.1 분할 유지 선택 모델

- 분할 패널 클릭/패널 이동 단축키는 `preserveSplitLayout` 모드로 세션 활성화
- 분할 컨텍스트에서 탭/패널 선택 시 분할 트리는 유지

### 4.2 VSCode 스타일 기본 분할

- 기본 분할을 "오른쪽 분할"로 정의
- `Ctrl+\` 단축키로 즉시 실행
- 툴바에 `기본` 버튼 추가

### 4.3 레이아웃 프리셋 선택기

- 툴바에 프리셋 `select + 적용` 추가
- `Ctrl+Shift+S`로 선택기에 포커스
- 팔레트에도 `레이아웃 선택기 열기` 커맨드 추가

## 5. 구현 반영 파일

- `src/app.js`
  - 분할 유지 활성화 옵션 (`activateSession(..., { preserveSplitLayout: true })`)
  - `splitDefault()`, `focusLayoutPresetSelector()`
  - 단축키: `Ctrl+\`, `Ctrl+Shift+S`
  - 툴바/컨텍스트/팔레트 액션 연결
- `index.html`
  - `splitDefaultBtn`
  - `layoutPresetSelect`, `applyLayoutPresetBtn`
- `src/style.css`
  - 분할/툴바 선택기 UI 스타일
- `src/__tests__/split-layout.e2e.test.js`
  - 분할 유지, 기본 분할 단축키, 프리셋 선택기 적용 테스트

## 6. 추가 추천 (후속)

1. 레이아웃 갤러리 모달
- 2열/2행/그리드/3열을 아이콘 프리뷰와 함께 제공

2. 패널 헤더 고급화
- 현재 경로, 프로젝트명, 실행 중 명령 요약 표시

3. 드래그 힌트 강화
- 분할 경계 근처 진입 시 미리보기 오버레이를 더 크게 표시

## 7. 결론

이번 개선으로 사용자는 분할 상태를 유지한 채 패널을 선택/탐색할 수 있고, 레이아웃 선택 진입도 더 직관적으로 접근할 수 있습니다.
다음 단계는 레이아웃 갤러리와 패널 상태 시각화 고도화가 적절합니다.
